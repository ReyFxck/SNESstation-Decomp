# Matching Phase 4: `mathfp` candidates

This checkpoint turns the Newlib 1.10.0 identification into reproducible EE
objects and records the first two byte-matching functions in the project.

## Reproduction contract

- compiler: isolated EE GCC 3.2.2 stage one from the pinned PS2DEV root recipe;
- backend patch: surviving BETA 3 patch, which postdates the January 2004 target;
- target listing: `analysis/functions/math_frontier_0019fddc.asm`;
- reconstructed listing-image SHA-256:
  `97ff4a34df3cc4fbf1dde4cca78f2ac148ad6d44a83280fa25615b0ff0ea365f`;
- flags: the recorded application flags, except `mathfp` deliberately removes
  `-fshort-double` because the four large target functions call the soft-double
  helpers generated by normal 64-bit `double` expressions.

Run the local evidence check with:

```bash
make bootstrap-ee-stage1
EE_CC="$PWD/build/toolchains/ee-gcc-3.2.2-stage1/prefix/bin/ee-gcc"
make match-mathfp-listing EE_CC="$EE_CC"
```

The committed report is
`analysis/matching/mathfp-listing-report.md`. `make match-mathfp` remains the
formal recheck against a user-supplied, hash-verified original ELF.

## Result

| Function | Target bytes | Candidate bytes | State |
|---|---:|---:|---|
| `cosf` | 584 | 588 | source/register scheduling still differs |
| `sinf` | 560 | 564 | source/alignment tail still differs |
| `tanf` | 520 | 524 | one four-byte layout difference remains |
| `atanf` | 580 | 572 | eight-byte source/layout gap remains |
| `sqrtf` | 8 | 8 | **MATCHING** |
| `fabsf` | 8 | 8 | **MATCHING** |
| `numtestf` | 128 | 88 | ABI shape recovered; exact library body/compiler remains open |

`sqrtf` is exactly `jr $ra` with `sqrt.s $f0,$f12` in the delay slot.
`fabsf` is exactly `jr $ra` with `abs.s $f0,$f12` in the delay slot. Neither
function has relocations, so no bytes are masked in those two results.

The old manifest incorrectly included each following eight-byte alignment gap
inside these functions. Their ranges are now correctly recorded as
`0x001a06a0..0x001a06a7` and `0x001a06b0..0x001a06b7`.

## Important ABI evidence

The four callers promote the argument before calling `numtestf`, but the target
`numtestf` body reads a float from `$f12`. The candidates therefore keep the
call sites non-prototyped and compile the float definition separately. A modern
single prototype hides this historical mismatch and produces misleading code.

The remaining large functions are close enough in size and control flow to
confirm the Newlib family, but the first surviving public PS2DEV compiler patch
is BETA 3 rather than the likely earlier `3.2.2-b1` build. They stay
`RECONSTRUCTED`, not `MATCHING`, until every non-relocation byte agrees.

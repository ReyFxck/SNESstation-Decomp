## Recovered ABI and source facts

The historical EE build uses `-mlong64`, but the PS2-facing C declarations in
these translation units still pass byte counts and return lengths as 32-bit
values. Modernized Newlib declarations widened `size_t`, inserting otherwise
unexplained `dsll32`/`dsrl32` pairs. A private compatibility include restores
the 32-bit declarations without changing the pinned upstream archive.

`CMemory::LoadROM` and the snapshot functions also prove that the target was
built with the zlib stream macros enabled. The SRAM functions bypass desktop
`FILE *` I/O and call the old PS2 `fio*` layer directly, using open flags `1`
for load and `0x203` for save.

Three diagnostic prints present in official Snes9x 1.41-1 are absent from the
target. The renderer likewise omits the frame-rate text overlay. These small
source deltas account exactly for the former 28-, 40- and 96-byte gaps; no
unrelated code is ignored or masked.

The `0x001434ac` audited boundary contains two adjacent historical symbols.
The runner requires both object symbols to occupy one section contiguously,
then compares their complete 480-byte concatenation with relocation masking
applied independently to each symbol.

## Reproduce

Place the private original at `original/SNES_EMU.ELF`, then run:

```sh
make reference
make hunt1041-v52-evidence EE_BUILD_JOBS=8
python3 tools/research/hunt1041_v52_closure.py --apply
make check
```

Machine-readable proof is in
[`hunt1041-v52-validated-17.tsv`](../analysis/matching/hunt1041-v52-validated-17.tsv).
The original ELF and generated `build/` objects remain ignored and must not be
committed or redistributed.

This is a function-level matching checkpoint, not yet a claim that the final
historical link or packed replacement ELF has been reproduced.

V48 promotes **25** strict matches, moving the audited checkpoint from

## Corrected function boundary

The old manifest began `mcStoreDir` at `0x001a0870`, after its first
instruction. The official 15 April 2004 PS2LIB object proves that the leading
`lui` at `0x001a086c` belongs to `mcStoreDir`. Moving the entry to
`0x001a086c` also upgrades the preceding `mcReadFixAlign` proof from a terminal
prefix to an exact 164-byte next-address boundary. The target count remains
1041; no entry was added or removed.

## Historical symbols split by the old manifest

Three compiler symbols were previously split at instructions before their
conventional stack prologues:

| Historical symbol | Full target range | Manifest slices |
|---|---:|---:|
| `unShrink` | `0x0018ea58..0x0018eeb4` | 12 + 1104 bytes |
| `unzGetCurrentFileInfo` | `0x0018faa4..0x0018faec` | 16 + 56 bytes |
| `inflate_fast` | `0x00195b3c..0x00195f80` | 4 + 1088 bytes |

The V48 runner requires the slices for each object symbol to form one exact,
non-overlapping partition of that symbol. This preserves the established
1041-entry audit while recording the true historical compiler ownership.

Four S-RTC helpers use the official Snes9x 1.41-1 bodies with the PS2 target's
time contract. `system_timestamp` is a 32-bit field at offset `0x14`, followed
by the existing 32-bit pad; the save/load format still copies the fixed eight
bytes beginning at that field. The frontend has no wall-clock provider, so its
three `time(NULL)` reads are zero. A private build copy encodes those ABI facts,
producing exact 728-, 312-, 232-, and 196-byte symbols for update, set,
pre-save, and post-load respectively.

`S9xGetWord` uses the official Snes9x 1.41-1 implementation with the target's
R5900 unaligned little-endian word-access primitive. A private header copy
enables `FAST_LSB_WORD_ACCESS`, models the four-byte packed read, and preserves
the target's `$16` allocation/truncation barrier. The resulting 1020-byte
symbol matches exactly; the official archive remains untouched.

PGEN's `gzread` is rebuilt with the old 32-bit `memcpy` length declaration
used by the target frontend. This removes the otherwise generated 64-bit size
extension while leaving the official function body unchanged; the resulting
676-byte symbol has an exact next-address boundary and zero differing bits.

The palette helper is the official `S9xFixColourBrightness` body. The target
selects the fixed `BGR555` pixel macro (red in the low five bits), rather than
the desktop multi-format path or `RGB555`; that private profile produces the
exact 192-byte symbol and leaves the official archive unchanged.

The committed `inflate_fast` listing contains two bounded eight-byte address
gaps at `0x00195f1c..0x00195f24` and `0x00195f5c..0x00195f64`. They are the
zero words suppressed in the continuous objdump output. No other absent bytes
are inferred. Their source hash and ranges are frozen in
[`hunt1041-v48-inferred-zero-ranges.tsv`](../analysis/matching/hunt1041-v48-inferred-zero-ranges.tsv).

## Reproduce

The hash-pinned unpacked original is the preferred target. If it is not present,
the runner uses only committed listing bytes plus the two bounded zero gaps
above:

```sh
make hunt1041-v48-evidence EE_BUILD_JOBS=8
python3 tools/research/hunt1041_v48_closure.py --apply
make check
```

The first command is non-mutating with respect to the manifests. The second
rebuilds and revalidates all 25 rows before promotion. Machine-readable evidence
is in
[`hunt1041-v48-validated-25.tsv`](../analysis/matching/hunt1041-v48-validated-25.tsv).

This is a function-level matching checkpoint, not a claim that a complete
replacement ELF or final historical link has been reproduced.
